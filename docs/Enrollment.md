# BaronDesk Agent : Station Enrollment (First Connection) Architecture

This document describes how a new station gets its identity the first time it contacts the backend (roadmap branch 4, planning *Auth & Security — Scenario Catalog* AS1/AS2, *Component — Enrollment & Provisioning*): the one-time enrollment token, the station key pair, the signed enrollment request, admin approval and the hand-over to the DPAPI credential store.

## 1. What the Station Sends on First Contact

Before the WSS link exists, the station has no credential. It proves three things in one signed request:

| Field | Security role |
|---|---|
| `oneTimeToken` (FROZEN) | Authorises *this* enrollment. Generated by an admin in the dashboard, single use, never logged |
| `mac`, `ip` (FROZEN) | Informational, shown to the approving admin. **MAC is not authentication** |
| `serialNumber`, `machineName`, `agentVersion` | Which station is asking (`Machine.serialNumber`) |
| `agentPublicKey` | Base64 DER SubjectPublicKeyInfo of the station's own **ECDSA P-256** key → `Machine.agentPublicKey` |
| `signedAt`, `signature` | Proof of possession of the matching private key, over the token, identity and key |

Signed input (UTF-8, joined with `\n`), ECDSA-SHA256, DER signature:

```text
BARONDESK-ENROLL-V1
<oneTimeToken>
<serialNumber>
<mac>
<ip>
<agentPublicKey>
<signedAt>
```

The **private key never leaves the station**: it is generated locally and kept as PKCS#8 in `station.key` (DPAPI, machine scope, SYSTEM + Administrators only). No shared secret is baked into the installer; every station has its own identity.

## 2. Flow

```text
Admin (dashboard)          Station (elevated prompt)          ServiceCore                         Backend
      │ generate one-time token     │                                │                                  │
      │────────────────────────────►│ --set-enrollment-token          │                                  │
      │                             │──► enrollment.token (DPAPI)     │                                  │
      │                             │                                │ start: no station credential     │
      │                             │                                │ create key pair → station.key    │
      │                             │                                │── TLS (pinned cert) ────────────►│
      │                             │                                │── POST /enrollment/request ─────►│ verify signature,
      │                             │                                │◄─ { status: "PENDING" } ─────────│ record public key
      │◄──────────────────────── approval request ─────────────────────────────────────────────────────│
      │ approve ───────────────────────────────────────────────────────────────────────────────────────►│
      │                             │                                │── same request, new signedAt ───►│ same key? newer?
      │                             │                                │◄─ { status: "ENROLLED",          │
      │                             │                                │     stationToken, machineId } ───│
      │                             │                                │ station.credential (DPAPI)       │
      │                             │                                │ delete enrollment.token          │
      │                             │                                │── WSS upgrade, Bearer <JWT> ────►│ (AS5 from here on)
```

| Answer | Agent behaviour |
|---|---|
| `PENDING` | Asks again every `EnrollmentPollSeconds` (default 15 s), same key, logged once |
| `ENROLLED` + valid `stationToken` | Stores the JWT in DPAPI, deletes the one-time token, continues to the WSS connect |
| `ENROLLED` without a usable token | Logged as an error, keeps polling |
| `REJECTED`, HTTP 401 / 403 / 410 | Deletes the spent token, logs CRITICAL, stays unenrolled (AS2) |
| Network error, 5xx, 400, bad JSON | Retries with the reconnect backoff (`ReconnectBaseDelaySeconds` … `ReconnectMaxDelaySeconds`) |

The station stays **locked** the whole time (fail closed). Enrollment runs only when there is no station credential **and** an enrollment token is provisioned; otherwise the connection behaves as before (see `CredentialStore.md` §5).

## 3. Transport Security

- `HttpEnrollmentClient` uses the **same certificate pin** as the WSS link (`CertificatePinning`). On a mismatch the TLS handshake fails, so the one-time token is never sent.
- No proxy, no redirects: the token can only go to the pinned server.
- Endpoint: `Agent:EnrollmentUrl`, or by default `https://<ServerUrl host:port>/enrollment/request` (`http://` only in Development).
- Responses are capped at 64 KB; the request times out after 15 s.

---

## 4. What the Backend Must Check (to confirm with backend member C)

> ⚠ OPEN (skill §15 item 8): Step 0 freezes only `POST /enrollment/request {oneTimeToken, mac, ip} → {status:"PENDING"}` and the admin `approve` / `revoke` endpoints. How the approved credential reaches the agent is not frozen. The agent **proposes** re-posting the same request and receiving `{ status: "ENROLLED", stationToken, machineId }`.

1. The token is valid, unexpired and not yet spent.
2. The `signature` verifies against `agentPublicKey` (Node: `crypto.verify('sha256', input, spkiKey, signature)`).
3. The first accepted request **pins** the public key to the pending machine. Later requests with another key are refused.
4. `stationToken` is released only to a request signed by that key with a `signedAt` newer than the previous one. Someone who steals the one-time token alone cannot collect the station credential.
5. `mac` / `ip` are shown to the approving admin; they are not trusted as identity.

The mock server implements 2 and 3 so the agent can be tested end to end.

## 5. Provisioning Commands (elevated prompt)

```powershell
# one-time token from the dashboard (piped or typed hidden, never as an argument)
"<one-time token>" | BaronDeskAgent.ServiceCore.exe --set-enrollment-token
BaronDeskAgent.ServiceCore.exe --clear-enrollment-token

# re-enroll a station (e.g. after revocation, AS4/AS30): forget the identity first
BaronDeskAgent.ServiceCore.exe --clear-station-token     # removes station.credential AND station.key
```

`--set-station-token` remains as a manual fallback (a JWT issued out of band).

Development only: `Agent:EnrollmentToken` may hold the one-time token in configuration (rejected at startup elsewhere, like `Agent:StationToken`).

## 6. Files

| File (`%ProgramData%\BaronDeskAgent\Data`) | Content | Lifetime |
|---|---|---|
| `enrollment.token` | One-time token (DPAPI) | Until `ENROLLED` / `REJECTED` |
| `station.key` | ECDSA P-256 private key, PKCS#8 (DPAPI) | Until `--clear-station-token`; regenerated if unreadable (a cloned disk image gets a new identity) |
| `station.credential` | Station JWT (DPAPI) | Until rotated / cleared |

All three use `ProtectedFile`: DPAPI `LocalMachine` with per-purpose entropy, protected DACL (SYSTEM + Administrators), atomic write with the final ACL, plaintext buffers zeroed.

## 7. Testing

`EnrollmentServiceTests` (fake client, fake clock):

| Test | Guarantees |
|---|---|
| `An_enrolled_station_never_contacts_the_enrollment_endpoint` | No enrollment once a credential exists |
| `Without_an_enrollment_token_nothing_is_sent` | No token → no request |
| `Pending_until_approved_then_the_credential_is_stored_and_the_token_forgotten` | Polling, same key every time, JWT stored, token deleted |

| `The_development_config_token_is_used_when_none_is_provisioned` | Config fallback, not deleted |
| `Neither_token_is_ever_logged` | No secret in any log message |

`DpapiStationKeyStoreTests`: key survives a restart, private key never on disk in plain text, unreadable key → new identity, delete forgets the identity.
